# Git-процесс

Формат коммитов и ветвление. Коротко и по факту.

## Сейчас (с 16.09.2026)
- **`main`** — то, что на motophd.com. Деплой — кнопкой из `main` (см. [ARCHITECTURE.md](./ARCHITECTURE.md#окружения-и-деплой)).
- **`dev`** — рабочая ветка с новым дизайном (бывшая `design` влита сюда). Аня работает только здесь:
  фича = ветка `feature/<slug>` от `dev` → PR в `dev` → зелёный CI → squash-merge. Прямой пуш в `dev`/`main` запрещён.
- Дима работает в `main` (задачи из Linear) и **регулярно вливает `main → dev`**, чтобы дизайн-ветка не отставала.
- **`dev → main`** — по команде «выкладывай»: PR `dev → main`, авто-слияние **merge-коммитом (не squash)**, затем деплой.
  Может запускать и Аня (её Claude), и Дима. Конфликты в этом PR разрешает только Дима.
- Сообщение — **Conventional Commits**: `feat:`, `fix:`, `docs:`, `chore:`, `refactor:`, `test:`.
- Любой набор изменений → агент **предлагает имя коммита**; решает и коммитит человек (для Ани — её Claude по команде «оформляй»).

## Примеры
```
chore(init): next.js + app router + scss + eslint
feat(i18n): локали en/ru через next-intl
feat(landing): перенос лендинга из прототипа
docs(gitflow): процесс коммитов
```
