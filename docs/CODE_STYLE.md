# Правила кода

Обязательны. Нарушение — долг к исправлению, а не «дело вкуса».

## 1. Размер файла

- Компоненты, хуки, логика — **≤ 200 строк** (цель 100–150). 200 — жёсткий максимум.
- Файлы стилей (`*.module.scss`) — **≤ 400 строк**.
- Данные и фикстуры — дробим по смыслу (курсы, отзывы, FAQ — отдельными файлами), не один свал.
- Упёрся в лимит → **дели**: выноси подкомпоненты, хук (`useX.ts`), утилиты, типы.
  Не «ужимай», а разбивай ответственность.

## 2. Компонент = папка (колокация)

Всё про компонент лежит рядом, чтобы папку можно было выдрать и вставить целиком.

```
components/CourseCard/
  CourseCard.tsx           # разметка + минимальная логика
  CourseCard.module.scss   # его стиль
  CourseCard.types.ts      # типы пропсов, если нетривиальные
  useCourseCard.ts         # хук, если логики много
  CourseCard.test.tsx      # тест
  index.ts                 # ре-экспорт
```

Стиль компонента — **только** в его `*.module.scss`. Общих монстро-файлов не существует.
Глобальных ровно два: `src/styles/` (переменные-токены) и `src/app/globals.scss` (база/reset).

## 3. Стили

- SCSS-модули + BEM. Tailwind и UI-киты не подключаем.
- Один `*.module.scss` = стиль одного компонента.
- Инлайн-стилей нет.

## 4. Декомпозиция

- Один файл — одна ответственность.
- `page.tsx` и `layout.tsx` — **тонкие**: композиция из компонентов, без вёрстки-простыни
  и без логики.
- Логику держим в `src/lib/`, не в компонентах.
- Инлайн-обработчиков в разметке нет.

## 5. Next.js

**Server / Client**

- Server Components по умолчанию. `'use client'` — только на листовых интерактивных компонентах,
  границу двигаем вниз.
- Данные грузим на сервере, не в `useEffect`.

**Структура**

- Абсолютные импорты через `@/`.
- `loading.tsx` / `error.tsx` / `not-found.tsx` на маршрутах, где уместно.
- `index.ts`-ре-экспорты — умеренно.

**Типы**

- Строгий TypeScript, ноль `any`. Пропсы — через `interface Props`.

**Производительность**

- `next/image`, `next/font`, `next/link` вместо ручных `<img>`, шрифтов и `<a>`.
- Мемоизация (`memo`, `useMemo`) — только по факту замера, не превентивно.

**Доступность и SEO**

- Семантическая разметка, `alt` у картинок, подписи у полей, управляемый фокус.
- Метаданные страниц — через Metadata API.

**Именование**

- PascalCase — компоненты, camelCase — функции и хуки.

## 6. Тесты

- Тест лежит рядом с тем, что проверяет.
- Меняешь поведение — пиши или обновляй тест.
- Образцы, на которые равняемся: `src/lib/access/hasPaidAccess.test.ts`,
  `src/components/prototype/FaqAccordion/FaqAccordion.test.tsx`, `e2e/smoke.spec.ts`.
- Работа закончена только при зелёных `pnpm lint`, `pnpm typecheck`, `pnpm test`.

## 7. Тексты

Хардкодить текст прямо в разметке нельзя. Подписи интерфейса — в `messages/en.json` и
`messages/ru.json`, содержание курсов — в панели управления сайтом (см. [ARCHITECTURE.md](./ARCHITECTURE.md)).
