# Поток S4 — Личный кабинет (F6)

Ветка `feature/cabinet-f6`. Сначала прочитай `docs/tbd/sprint/COORDINATION.md`.
Затем: `AGENTS.md`, `docs/TZ.md` F6, `docs/BUSINESS_RULES.md` (Аккаунты, Деньги),
текущий код: `src/components/dashboard/` (DashboardClient/Cards/Panels),
`src/app/(app)/[locale]/dashboard/`, `src/lib/auth/`, `src/lib/data/courses.ts`
(`getDashboardCourses`), `src/collections/Users.ts`, `src/collections/Purchases.ts`.

**Зачем:** кабинет сейчас — карточки курсов + хардкод-статистика («1 курс», «40%»).
По ТЗ F6 нужны: профиль, смена пароля, история покупок, удаление аккаунта, докупка
feedback. Прогресса в продукте НЕТ (ADR-9) — ничего про проценты не строить.

## Scope

1. **Выпилить хардкод** из `DashboardPanels` (проценты/статистика) — вместо него
   реальные данные: количество купленных курсов, ссылки.
2. **Профиль**: поле имени. Проверь `src/collections/Users.ts` — если поля `name` нет,
   добавь (+ миграция через `pnpm payload migrate:create`, руками не писать).
   Форма в кабинете: имя (редактируемое), email (read-only). Server actions клади в
   новый `src/lib/auth/account.ts` — существующие файлы `lib/auth/` не менять.
3. **Смена пароля**: текущий пароль + новый ×2; проверка текущего через
   `payload.login`, смена через `payload.update` на себя. После смены — сессия жива.
4. **История покупок**: список своих `Purchases` (курс, тариф, сумма, валюта, дата,
   статус). Только свои — запрос от имени юзера, `overrideAccess: false`.
5. **Удаление аккаунта**: кнопка с подтверждением (ввести слово или email).
   Рекомендация: `payload.delete` юзера; если связь в `Purchases.user` этого не даёт
   (required/FK) — покупки анонимизировать (user → null) до удаления. Реши по факту
   схемы, зафиксируй решение в отчёте. После удаления — logout и редирект на главную.
6. **Докупка feedback**: у купленного standard-курса CTA «добавить обратную связь»,
   вызывающий `createCheckout({ courseSlug, tier: 'feedback_upgrade', locale })` —
   контракт в COORDINATION.md. Поток S2 пилит его параллельно: пиши вызов по
   контракту; если импорт не резолвится — вынеси кнопку в компонент с TODO-маркером
   `TODO(checkout-wire)` и задокументируй в отчёте «для интеграции».

Namespace в `messages/*.json` — `dashboard` (расширяй существующий, если есть).
Новые зависимости: никаких.

## Тесты
Юнит на actions (смена пароля: неверный текущий = ошибка; удаление: покупки
обрабатываются по выбранному решению). Компонентный на историю покупок.
Свой e2e-кейс: смена пароля → релогин новым паролем.
