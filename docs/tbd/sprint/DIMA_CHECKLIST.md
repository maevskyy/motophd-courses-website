# Чек-лист Димы на спринт (руками, параллельно потокам)

Отсортировано по внешним задержкам: первым — то, что «зреет» само (DNS), пока ты
делаешь остальное.

## 0. Запуск потоков (5 мин)

В каждой Codex-сессии — одна строка:
`Прочитай docs/tbd/sprint/stream_<имя>.md и выполни его.`
Потоки: media, payments, emails_f9, cabinet, consent, observability, hardening.
Все ветвятся от свежего `main`. Открытые вопросы грум-задач считаются решёнными
по рекомендациям грумеров — потоки так и проинструктированы.

## 1. Resend — СНАЧАЛА (10 мин работы + DNS зреет до часа)

- resend.com → аккаунт → Add domain `motophd.com` → выдаст DKIM/SPF-записи.
- Добавить записи в Cloudflare DNS → в Resend нажать Verify (может провисеть
  10–60 мин — поэтому первым).
- Create API Key → в локальный `.env`: `RESEND_API_KEY=...`,
  `EMAIL_FROM="MotoPhD <no-reply@motophd.com>"`. Позже — на бокс.

## 2. Cloudflare R2 + Stream (~30–40 мин)

Готовый пошаговый список — раздел **«Ручные шаги (Дима, консоль Cloudflare)»**
в `docs/kanban/todo/task_media_stream_5.md` (бакет `motophd-media`, токен, Stream-подписка,
тестовое видео с Require signed URLs, signing key, UID в админку). Плюс для бэкапов:
- Второй бакет `motophd-backups` (EU) + отдельный API-токен Object Read & Write
  только на него → env `BACKUP_R2_*` (имена даст поток observability).

## 3. Telegram-бот для алертов (5 мин)

@BotFather → новый бот → токен. Написать боту что-нибудь, взять chat_id
(`https://api.telegram.org/bot<TOKEN>/getUpdates`). → `TG_BOT_TOKEN`, `TG_CHAT_ID`
(на бокс, в `~/motophd/.env`).

## 4. Cloudflare Access (10 мин, можно после мержа hardening)

Zero Trust → Access → Self-hosted app на `admin.motophd.com` и `grafana.motophd.com`,
policy: email-allowlist (ты, Аня, Влад). Точная инструкция будет в
`docs/RUNBOOK_VPS.md` от потока hardening.

## 5. WayForPay — СЕГОДНЯ НЕ ДЕЛАТЬ

Боевой мерчант невозможен без ФОП Влада (внешний блокер, ТЗ §8), а грум-задача
подняла два серьёзных вопроса до боевого подключения (зачисление только в гривне,
регуляторный риск НБУ) — решение о боевом PSP принимается отдельно, не сегодня.
Mock-провайдер покрывает весь флоу, скелет WayForPay работает на env-ключах, когда
появятся. Час на регистрацию кабинета сегодня — потерянный час.

## 6. Интеграция (после финиша потоков — самая важная часть)

Порядок мержа и шаги — раздел «Порядок мержа» в `COORDINATION.md`:
media → payments → emails → cabinet → consent (+ observability и hardening независимо).
После всех: чистая БД → migrate → seed → build → полный e2e. Затем: применение
конфигов на VPS по `deploy/monitoring/APPLY.md`, деплой, kanban-хозяйство (14–16 в done).
Интеграцию можно отдать оркестратору (этой сессии) — вернись с «потоки готовы».
